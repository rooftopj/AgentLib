# Claude Code 源码解析（01）Memory：文件化长期记忆、相关召回与会话压缩

## 先给结论

Claude Code 的 Memory 不是一个单独的向量库功能。它由几条线拼起来：auto-memory 保存跨 session 的长期上下文，`relevant_memories` 在 query 时按需注入 topic files，session memory 给当前会话 compact 用，team memory 和 agent memory 是可选扩展。

## Memory 家族

`CLAUDE.md` 会和 memory files 一起进入上下文，但它更像项目说明和规则；auto-memory 才承担跨 session 长期记忆的主轴。两者都会影响模型输入，但生命周期完全不同。

```ts
// assets/projects/claude-code/src/context.ts
const claudeMd = shouldDisableClaudeMd
  ? null
  : getClaudeMds(filterInjectedMemoryFiles(await getMemoryFiles()))
```

这段说明启动上下文时会读取 memory files，再交给 `getClaudeMds` 汇总。后面 query 侧还会另走一条 relevant memory prefetch，专门把相关 topic files 作为 attachment 注入。

```text

# 3 assets/projects/claude-code/src/services/extractMemories/extractMemories.ts

# 5 assets/projects/claude-code/src/utils/attachments.ts

```

## auto-memory 主轴

auto-memory 默认开启，但会被环境、bare/simple 模式、remote memory 目录和 settings 关掉。默认路径是 `<memoryBase>/projects/<sanitized-project>/memory/`，其中 `MEMORY.md` 是入口索引。

```ts
// assets/projects/claude-code/src/memdir/paths.ts
export function isAutoMemoryEnabled(): boolean {
  const envVal = process.env.CLAUDE_CODE_DISABLE_AUTO_MEMORY
  if (isEnvTruthy(envVal)) return false
  if (isEnvDefinedFalsy(envVal)) return true
  if (isEnvTruthy(process.env.CLAUDE_CODE_SIMPLE)) return false
  return getInitialSettings().autoMemoryEnabled ?? true
}
```

`MEMORY.md` 有硬上限：200 行和 25KB。这个限制本身就是架构信号：它不是正文库，而是短索引。真正的内容应该写进按主题组织的 Markdown 文件。

```ts
// assets/projects/claude-code/src/memdir/memdir.ts
export const ENTRYPOINT_NAME = 'MEMORY.md'
export const MAX_ENTRYPOINT_LINES = 200
export const MAX_ENTRYPOINT_BYTES = 25_000
```

## 写入什么时候触发

写入有三条主路径。第一条是主 agent 按系统提示或用户明确要求 remember/forget 直接写。第二条是 `/memory` 命令打开文件给人手工编辑。第三条是 `extractMemories` 在 stop hook 后台 fork 一个 agent 补写。

  caption="生命周期：显式写入、后台抽取、文件持久化、相关召回、session compact 和 autoDream 整理。"

```ts
// assets/projects/claude-code/src/query/stopHooks.ts
if (feature('EXTRACT_MEMORIES') && !toolUseContext.agentId && isExtractModeActive()) {
  void extractMemoriesModule!.executeExtractMemories(
    stopHookContext,
    toolUseContext.appendSystemMessage,
  )
}

if (!toolUseContext.agentId) {
  void executeAutoDream(stopHookContext, toolUseContext.appendSystemMessage)
}
```

这不是一个叫 `observe()` 的公开 API，但语义上很像“回合结束后的观察”。用户 turn 完成后，Claude Code 在主响应路径之外启动记忆抽取和梦境整理。

## 写入什么内容

长期记忆被约束成四类：`user`、`feedback`、`project`、`reference`。它们都要求保存“当前代码、git、CLAUDE.md 无法直接推出”的上下文。

```ts
// assets/projects/claude-code/src/memdir/memoryTypes.ts
export const MEMORY_TYPES = [
  'user',
  'feedback',
  'project',
  'reference',
] as const
```

`user` 保存用户角色、目标和知识背景；`feedback` 保存用户对协作方式的纠正或确认；`project` 保存项目目标、约束、事故和期限；`reference` 保存外部系统入口。

## 存储形态

每条长期记忆是带 frontmatter 的 Markdown 文件。`name` 和 `description` 用于后续相关性判断，`type` 限制为四类之一，正文写具体可复用内容。

```ts
// assets/projects/claude-code/src/memdir/memoryTypes.ts
export const MEMORY_FRONTMATTER_EXAMPLE: readonly string[] = [
  '---',
  'name: {{memory name}}',
  'description: {{one-line description}}',
  `type: {{${MEMORY_TYPES.join(', ')}}}`,
  '---',
]
```

session memory 另走一套路径。它保存在 `{projectDir}/{sessionId}/session-memory/summary.md`，用途是当前长会话的压缩，不是跨 session 的用户偏好库。

```ts
// assets/projects/claude-code/src/utils/permissions/filesystem.ts
export function getSessionMemoryPath(): string {
  return join(getSessionMemoryDir(), 'summary.md')
}
```

## 冲突与更新

Claude Code 没有结构化 `supersede` 表，也没有 `to_dict` 后写入事实数据库。它的 dedup、conflict 和 update 主要靠“先查旧文件，再改旧文件”的 prompt 规则、后台 manifest、主 agent 与 extractor 互斥，以及 autoDream 的周期整理。

## 召回什么时候触发

召回分两层。第一层发生在 `getUserContext`：`MEMORY.md` 作为索引和 memory 指令进入上下文。第二层发生在每个用户 turn：`startRelevantMemoryPrefetch()` 启动异步选择器，主模型工作时它并行找相关 topic files。

```ts
// assets/projects/claude-code/src/query.ts
using pendingMemoryPrefetch = startRelevantMemoryPrefetch(
  state.messages,
  state.toolUseContext,
)
```

prefetch 不阻塞主 turn。`query.ts` 在工具执行后的收集点检查它是否 settled；如果已经完成，就把 memory attachments 注入，否则下一轮 iteration 再尝试。

## 怎么检索

更精确地说，Claude Code 默认不是 BM25，也不是 vector search。`findRelevantMemories()` 先扫描 Markdown frontmatter 形成 manifest，再让 `sideQuery` 基于用户 query、文件名和 description 选择最多 5 个文件。

```ts
// assets/projects/claude-code/src/memdir/findRelevantMemories.ts
const result = await sideQuery({
  model: getDefaultSonnetModel(),
  system: SELECT_MEMORIES_SYSTEM_PROMPT,
  messages: [{
    role: 'user',
    content: `Query: ${query}\n\nAvailable memories:\n${manifest}${toolsSection}`,
  }],
  querySource: 'memdir_relevance',
})
```

选中文件后，`readMemoriesForSurfacing()` 只读每个文件前 200 行和 4KB。session 累计最多 60KB，且会过滤已经读过、写过或注入过的记忆。

```ts
// assets/projects/claude-code/src/utils/attachments.ts
const MAX_MEMORY_LINES = 200
const MAX_MEMORY_BYTES = 4096

export const RELEVANT_MEMORIES_CONFIG = {
  MAX_SESSION_BYTES: 60 * 1024,
} as const
```

所以“检索”不是向量相似度，而是：frontmatter manifest -> sideQuery selector -> 截断读取 -> attachment 注入 -> readFileState 去重。

## Session Memory

session memory 是另一个问题：如何在长会话 compact 后保留当前工作状态。它不是长期记忆，也不会表达用户长期偏好。它在 post-sampling hook 中按 token 和 tool-call 门槛更新 `summary.md`。

```ts
// assets/projects/claude-code/src/services/SessionMemory/sessionMemory.ts
export function shouldExtractMemory(messages: Message[]): boolean {
  const currentTokenCount = tokenCountWithEstimation(messages)
  const hasMetTokenThreshold = hasMetUpdateThreshold(currentTokenCount)
  const toolCallsSinceLastUpdate = countToolCallsSince(messages)
  return hasMetTokenThreshold || toolCallsSinceLastUpdate >= getToolCallsBetweenUpdates()
}
```

compact 时，`trySessionMemoryCompaction()` 等待抽取完成，读取 `summary.md`，再把它变成 compact summary message。这里解决的是“当前会话太长”，不是“未来会话怎么记住用户”。

## autoDream

`autoDream` 是长期记忆的清理和合并机制。默认至少 24 小时、5 个 session 才运行，并且拿 consolidation lock，避免多个整理任务同时改 memory 文件。

```ts
// assets/projects/claude-code/src/services/autoDream/autoDream.ts
const DEFAULTS: AutoDreamConfig = {
  minHours: 24,
  minSessions: 5,
}

const result = await runForkedAgent({
  querySource: 'auto_dream',
  forkLabel: 'auto_dream',
  canUseTool: createAutoMemCanUseTool(memoryRoot),
})
```

它的价值在冲突更新和索引卫生：合并重叠记忆，删除陈旧内容，保持 `MEMORY.md` 是短索引，而不是越写越长的正文堆。

## Team Memory 和 Agent Memory

team memory 是共享层，依赖 auto-memory 开启。它有 team 路径、watcher、pull/push、ETag/412 retry 和 secret scanner。对 Memory 主轴来说，关键是它复用文件化范式；同步语义和安全边界则比本地 memory 更复杂。

agent memory 是按 agent type 隔离的持久目录，scope 有 `user`、`project`、`local` 三种。被 @mention 的 agent 会优先搜索自己的 memory dir，而不是普通 auto-memory dir。

```ts
// assets/projects/claude-code/src/tools/AgentTool/agentMemory.ts
export type AgentMemoryScope = 'user' | 'project' | 'local'

export function getAgentMemoryDir(
```

## 可复用设计

- **把索引和正文分开**：`MEMORY.md` 控制上下文成本，topic files 保存细节。
- **用后台 fork，但要互斥**：主 agent 已写时 extractor 跳过，减少重复与冲突。
- **召回不要只靠索引**：索引给方向，prefetch 注入正文，模型再验证当前源码。
- **权限要落在工具层**：extractor 只能写 memory dir，session memory 只能 Edit 指定 summary。
- **区分长期记忆和会话摘要**：跨 session profile 和当前 session compact 是两个问题。

## 边界

这套设计牺牲了结构化一致性。没有默认 vector/embedding，也没有数据库级 dedup、merge、supersede；如果 description 写得差，sideQuery selector 可能漏掉相关 topic。

另一个边界是同步复杂度。team memory 还涉及 secret、防冲突、删除是否传播、server wins 或 local wins 的语义。这里的关键关系是：team memory 仍然延续 Markdown 文件化记忆，但一旦进入共享层，就要额外处理多端同步和安全审查。

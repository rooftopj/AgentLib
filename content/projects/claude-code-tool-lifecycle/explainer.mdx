# Claude Code 源码解析（06）Tool 调度与工具结果生命周期

## 先给结论

Claude Code 的 tool call 不是把模型输出拿来 `for` 一遍。它先在模型流中收集 `tool_use`，再交给调度器判断并发或独占；每个工具进入统一执行管线，最后 `tool_result` 还要经过持久化和预算压缩，才会回到下一轮上下文。

## Query Loop 先发现工作项

模型返回 assistant stream 时，`query.ts` 会持续收集 `tool_use` block。启用 streaming tool execution 时，工具不是等整段 assistant 完全结束后才开始跑，而是在 tool_use 出现时交给 `StreamingToolExecutor.addTool()`。

```ts
// assets/projects/claude-code/src/query.ts
const useStreamingToolExecution = config.gates.streamingToolExecution
let streamingToolExecutor = useStreamingToolExecution
  ? new StreamingToolExecutor(
      toolUseContext.options.tools,
      canUseTool,
      toolUseContext,
    )
  : null
```

模型流结束后，系统还要把剩余结果收干净。流式路径调用 `getRemainingResults()`，非流式路径调用 `runTools()`。

```ts
// assets/projects/claude-code/src/query.ts
const toolUpdates = streamingToolExecutor
  ? streamingToolExecutor.getRemainingResults()
  : runTools(toolUseBlocks, assistantMessages, canUseTool, toolUseContext)
```

## Tool 接口先声明调度契约

`Tool.ts` 里的 `Tool` 类型不是只有 `call()`。调度器要依赖 `isConcurrencySafe()`，权限层要依赖 `checkPermissions()`，结果层要依赖 `mapToolResultToToolResultBlockParam()` 和 `maxResultSizeChars`。

```ts
// assets/projects/claude-code/src/Tool.ts
export type Tool<TInput extends zod.ZodRawShape = zod.ZodRawShape, TOutput = unknown> = {
  name: string
  call(
    args: zod.infer<zod.ZodObject<TInput>>,
    context: ToolUseContext,
    canUseTool: CanUseToolFn,
    parentMessage: AssistantMessage,
    onProgress?: (progress: ToolProgress) => void,
  ): Promise<ToolResult<TOutput>>
  isConcurrencySafe(input: zod.infer<zod.ZodObject<TInput>>): boolean
  maxResultSizeChars: number
  mapToolResultToToolResultBlockParam(
    result: TOutput,
    toolUseId: string,
  ): ToolResultBlockParam
}
```

`buildTool()` 的默认值很保守：不声明并发安全的工具默认独占。这样新工具不会因为忘记写调度策略而被并发执行。

```ts
// assets/projects/claude-code/src/Tool.ts
isConcurrencySafe: options.isConcurrencySafe ?? (() => false),
isReadOnly: options.isReadOnly ?? (() => false),
```

## 非流式调度按批次执行

`toolOrchestration.ts` 是非流式 fallback。它先用 `partitionToolCalls()` 把 tool use 分批：连续的并发安全工具放进同一批，独占工具单独成批。

```ts
// assets/projects/claude-code/src/services/tools/toolOrchestration.ts
for (const toolUse of toolUseMessages) {
  const tool = findToolByName(toolUseContext.options.tools, toolUse.name)
  const isConcurrencySafe = tool?.isConcurrencySafe(toolUse.input as never)

  if (isConcurrencySafe) {
    currentBatch.push(toolUse)
  } else {
    if (currentBatch.length > 0) batches.push(currentBatch)
    batches.push([toolUse])
    currentBatch = []
  }
}
```

同一批并发工具会走 `runToolsConcurrently()`，并发上限来自环境变量，默认 10。独占批次会走 `runToolsSerially()`。

```ts
// assets/projects/claude-code/src/services/tools/toolOrchestration.ts
function getMaxToolUseConcurrency(): number {
  const envValue = process.env.CLAUDE_CODE_MAX_TOOL_USE_CONCURRENCY
  if (envValue) {
    const parsed = parseInt(envValue, 10)
    if (!isNaN(parsed) && parsed > 0) return parsed
  }
  return 10
}
```

## 流式调度是状态机

`StreamingToolExecutor` 的核心不是“并发池”，而是状态机。每个工具有 `queued`、`executing`、`completed`、`yielded` 四种状态，还会缓存 progress 和最终 message。

```ts
// assets/projects/claude-code/src/services/tools/StreamingToolExecutor.ts
type TrackedTool = {
  block: ToolUseBlock
  assistantMessage: AssistantMessage
  status: 'queued' | 'executing' | 'completed' | 'yielded'
  isConcurrencySafe: boolean
  messages: Array<MessageUpdate>
  pendingProgress: Array<MessageUpdate>
}
```

并发判断非常直接：当前没有执行中工具，或者新工具并发安全且所有执行中工具也并发安全。只要有一个独占工具在跑，后面的工具就不能启动。

```ts
// assets/projects/claude-code/src/services/tools/StreamingToolExecutor.ts
private canExecuteTool(isConcurrencySafe: boolean): boolean {
  const executingTools = this.trackedTools.filter(t => t.status === 'executing')
  if (executingTools.length === 0) return true
  return isConcurrencySafe && executingTools.every(t => t.isConcurrencySafe)
}
```

## 结果顺序由 Executor 兜住

`getCompletedResults()` 先吐出所有 pending progress，然后只输出已经完成且轮到顺序的最终结果。遇到正在执行的独占工具时，它会停止向后看，避免后续结果越过独占工具。

```ts
// assets/projects/claude-code/src/services/tools/StreamingToolExecutor.ts
async *getCompletedResults(): AsyncGenerator<MessageUpdate> {
  for (const tool of this.trackedTools) {
    while (tool.pendingProgress.length > 0) {
      yield tool.pendingProgress.shift()!
    }
  }

  for (const tool of this.trackedTools) {
    if (tool.status === 'yielded') continue
    if (tool.status === 'completed') {
      tool.status = 'yielded'
      for (const message of tool.messages) yield message
    } else if (tool.status === 'executing' && !tool.isConcurrencySafe) {
      break
    } else {
      break
    }
  }
}
```

流式路径还有一个重要细节：Bash 工具出错会中断 sibling Bash。读文件、WebFetch 这类失败不一定要把同批工具全部停掉。

```ts
// assets/projects/claude-code/src/services/tools/StreamingToolExecutor.ts
if (update.message?.type === 'user' && update.message.isMeta === false) {
  const isError = update.message.message.content.some(
    block => block.type === 'tool_result' && block.is_error,
  )
  if (isError && toolDefinition.name === 'Bash') {
    this.hasErrored = true
    this.siblingAbortController.abort('sibling_error')
  }
}
```

## 单工具生命周期从校验开始

调度器只负责“什么时候跑”。真正跑一个工具时，会进入 `runToolUse()`，再进入 `streamedCheckPermissionsAndCallTool()` 和 `checkPermissionsAndCallTool()`。

```ts
// assets/projects/claude-code/src/services/tools/toolExecution.ts
const tool = findToolByName(toolUseContext.options.tools, toolUse.name)
if (!tool) {
  return [createUnknownToolResult(toolUse)]
}

for await (const update of streamedCheckPermissionsAndCallTool(
  tool,
  toolUse.id,
  toolInput,
  toolUseContext,
  canUseTool,
  assistantMessage,
  messageId,
  requestId,
  mcpServerType,
  mcpServerBaseUrl,
)) {
  yield update
}
```

执行管线的第一层是输入校验。schema 或 `validateInput()` 失败时，系统直接返回 error tool_result，工具本体不会被调用。

```ts
// assets/projects/claude-code/src/services/tools/toolExecution.ts
const isValidResult = tool.inputSchema.safeParse(input)
if (!isValidResult.success) {
  return [{
    message: createUserMessage({
      content: [{ type: 'tool_result', tool_use_id: toolUseID, is_error: true, content }],
      toolUseResult: `Error: ${content}`,
    }),
  }]
}
```

## Hooks 和 Permission 包住 tool.call

PreToolUse hook 在 permission 前运行。它可以产生附件和进度，可以改 input，也可以阻断继续。之后 `resolveHookPermissionDecision()` 把 hook permission result 与 `canUseTool` 合并。

```ts
// assets/projects/claude-code/src/services/tools/toolExecution.ts
for await (const hookResult of runPreToolUseHooks(
  toolUseContext,
  tool,
  toolUseID,
  messageId,
  processedInput,
  requestId,
  mcpServerType,
  mcpServerBaseUrl,
)) {
  hookMessages.push(hookResult)
}

const resolved = await resolveHookPermissionDecision(
  hookPermissionResult,
  tool,
  processedInput,
  toolUseContext,
  canUseTool,
  assistantMessage,
  toolUseID,
)
```

只有最终决策是 allow，才会调用 `tool.call()`。调用时会把 `toolUseId`、`userModified`、上下文和 `onProgress` 都传进去。

```ts
// assets/projects/claude-code/src/services/tools/toolExecution.ts
const result = await tool.call(
  callInput as never,
  {
    ...toolUseContext,
    toolUseId: toolUseID,
    userModified: permissionDecision.updatedInput !== undefined,
  },
  canUseTool,
  assistantMessage,
  onProgress,
)
```

## Result Mapping 不是简单 stringify

工具返回的是内部 `ToolResult<TOutput>`。要进入 Claude API，必须用工具自己的 `mapToolResultToToolResultBlockParam()` 转成 `tool_result` block。

```ts
// assets/projects/claude-code/src/services/tools/toolExecution.ts
const mappedToolResultBlock = tool.mapToolResultToToolResultBlockParam(
  result.data as never,
  toolUseID,
)

const addToolResult = async (overrideMappedToolResultBlock?: ToolResultBlockParam) => {
  const toolResultBlock = overrideMappedToolResultBlock
    ? await processPreMappedToolResultBlock(tool, overrideMappedToolResultBlock, toolUseID)
    : await processToolResultBlock(tool, result.data, toolUseID)
  toolResultMessages.push(createUserMessage({ content: [toolResultBlock] }))
}
```

非 MCP 工具会先把 tool_result 放进消息，再跑 PostToolUse hook。MCP 工具相反，因为 PostToolUse hook 可以更新 MCP 输出。

```ts
// assets/projects/claude-code/src/services/tools/toolExecution.ts
if (!tool.isMcp) {
  await addToolResult()
}

for await (const hookResult of runPostToolUseHooks(...)) {
  hookMessages.push(hookResult)
}

if (tool.isMcp) {
  await addToolResult(hookUpdatedMCPOutput ?? mappedToolResultBlock)
}
```

## 第一层结果治理是单次持久化

`toolResultStorage.ts` 先处理单个 tool_result。超过工具自己的 `maxResultSizeChars` 时，内容会写入当前 session 的 `tool-results` 目录，上下文里只保留路径和预览。

```ts
// assets/projects/claude-code/src/utils/toolResultStorage.ts
const TOOL_RESULTS_SUBDIR = 'tool-results'

export function getToolResultsDir(): string | null {
  const projectDir = getProjectDir(getOriginalCwd())
  const sessionId = getSessionId()
  if (!projectDir || !sessionId) return null
  return path.join(projectDir, sessionId, TOOL_RESULTS_SUBDIR)
}
```

持久化后的 message 会变成 `<persisted-output>`。这不是为了 UI 好看，而是为了让模型知道完整结果在哪，同时避免把巨大文本原样塞回上下文。

```ts
// assets/projects/claude-code/src/utils/toolResultStorage.ts
function buildLargeToolResultMessage(result: PersistedToolResult): string {
  return `<persisted-output>
Full output has been saved to: ${result.path}

Preview:
${result.preview}
</persisted-output>`
}
```

## 第二层结果治理是历史预算

下一轮模型调用前，`query.ts` 会调用 `applyToolResultBudget()`。它处理的是历史 messages 里聚合后的 tool_result 预算，运行在 microcompact 前。

```ts
// assets/projects/claude-code/src/query.ts
messagesForQuery = await applyToolResultBudget(
  messagesForQuery,
  toolUseContext.contentReplacementState,
  persistReplacements
    ? records => void recordContentReplacement(records, toolUseContext.agentId).catch(logError)
    : undefined,
  new Set(
    toolUseContext.options.tools
      .filter(t => !Number.isFinite(t.maxResultSizeChars))
      .map(t => t.name),
  ),
)
```

`ContentReplacementState` 会记录已经见过和已经替换过的 tool result。已经替换的内容要稳定复用，避免每轮生成不同文本破坏 prompt cache。

```ts
// assets/projects/claude-code/src/utils/toolResultStorage.ts
export type ContentReplacementState = {
  seenIds: Set<string>
  replacements: Map<string, ContentReplacement>
}
```

## Bash 结果有自己的形态

Bash 默认结果上限是 30,000 字符。它还支持结构化输出、图片输出、background task 和已经持久化的 raw output。

```ts
// assets/projects/claude-code/src/tools/BashTool/BashTool.tsx
maxResultSizeChars: 30_000,
isConcurrencySafe(input) {
  return this.isReadOnly?.(input) ?? false
},
```

`mapToolResultToToolResultBlockParam()` 会处理 `persistedOutputPath`。这说明 Bash 有时在工具内部已经把长输出写好了，结果层只负责把路径和预览包进 tool_result。

## MCP 和 ToolSearch 是动态工具边界

MCP 工具由服务端 tool 动态转换成 Claude Code `Tool`。它默认 `isMcp=true`，输出可以包含 `structuredContent`、图片和 `_meta`。

```ts

```

## Failure Hook 保留错误生命周期

工具失败不是简单 throw。`toolExecution.ts` 会记录 telemetry，然后运行 `runPostToolUseFailureHooks()`。最终仍然返回 error `tool_result`，让模型能基于错误继续。

```ts
// assets/projects/claude-code/src/services/tools/toolExecution.ts
for await (const hookResult of runPostToolUseFailureHooks(
  toolUseContext,
  tool,
  toolUseID,
  messageId,
  processedInput,
  content,
  isInterrupt,
  requestId,
  mcpServerType,
  mcpServerBaseUrl,
)) {
  hookMessages.push(hookResult)
}
```

错误消息保留 `tool_use_id`，这是对话协议的关键。模型需要看到“哪一次 tool_use 失败了”，而不是只看到一段普通用户文本。

```ts
// assets/projects/claude-code/src/services/tools/toolExecution.ts
content: [
  {
    type: 'tool_result',
    content,
    is_error: true,
    tool_use_id: toolUseID,
  },
],
```

## 这套设计的关键取舍

Claude Code 把工具系统拆成“调度、执行、结果”三层，最大的收益是复杂工具可以继续统一接入。Bash、Agent、MCP、ToolSearch 的内部差异很大，但外部都要服从 tool_use 到 tool_result 的协议。

## 可复用设计

把工具并发能力做成工具自声明，而不是在调度器里写工具名白名单。调度器只关心 `isConcurrencySafe(input)`，工具自己负责判断当前输入是否安全。

把 `tool.call()` 包进统一生命周期。schema、hooks、permission、progress、post hook、failure hook 都有固定插槽，工具作者只需要实现核心业务逻辑。

把结果治理分成两层。单次超大输出先落盘，历史上下文再做稳定替换。这样既能保留可追溯文件，又能保护 prompt cache 和上下文预算。

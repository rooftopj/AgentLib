# Claude Code 源码解析（06）Tool 调度与工具结果生命周期

## 先给结论

Claude Code 的 tool call 不是把模型输出拿来顺序 `for` 一遍。它先从 assistant stream 中识别 `tool_use`，再由调度层判断流式执行、并发安全和独占顺序；单个工具进入统一执行管线，经过 schema、hook、permission、`tool.call()`、result mapping 和 failure hook；最后 `tool_result` 还要经过单次大输出持久化和历史 aggregate budget，才会进入下一轮模型上下文。

## Query Loop 先发现工作项

模型返回的是 assistant stream，`query.ts` 要边消费边收集 `tool_use` block。启用 streaming tool execution 时，工具可以在 assistant 还没完全结束前交给 `StreamingToolExecutor.addTool()`；否则等 assistant 消息结束后走 `runTools()`。

```ts
// assets/projects/claude-code/src/query.ts
const useStreamingToolExecution = config.gates.streamingToolExecution
let streamingToolExecutor = useStreamingToolExecution
  ? new StreamingToolExecutor(
      toolUseContext.options.tools,
      canUseTool,
      toolUseContext,
    )
  : null
```

模型流结束或被中断后，query loop 必须收尾工具结果。流式路径调用 `getRemainingResults()`，非流式路径调用 `runTools()`。这一步保证每个已经出现的 `tool_use` 都有匹配的 `tool_result`，否则 Claude API 的消息结构会断裂。

```ts
// assets/projects/claude-code/src/query.ts
const toolUpdates = streamingToolExecutor
  ? streamingToolExecutor.getRemainingResults()
  : runTools(toolUseBlocks, assistantMessages, canUseTool, toolUseContext)
```

## Tool 接口声明调度与结果契约

`Tool.ts` 里的 `Tool` 类型不仅是 `call()`。调度器依赖 `isConcurrencySafe()`，权限层依赖 `checkPermissions()`，结果层依赖 `maxResultSizeChars` 和 `mapToolResultToToolResultBlockParam()`。

```ts
// assets/projects/claude-code/src/Tool.ts
export type Tool<TInput extends zod.ZodRawShape = zod.ZodRawShape, TOutput = unknown> = {
  name: string
  call(...): Promise<ToolResult<TOutput>>
  isConcurrencySafe(input: zod.infer<Input>): boolean
  maxResultSizeChars: number
  mapToolResultToToolResultBlockParam(
    result: TOutput,
    toolUseId: string,
  ): ToolResultBlockParam
}
```

`buildTool()` 的默认调度策略很保守：没有声明并发安全的工具默认不能并发。这让新工具不至于因为忘写策略而被并行执行。

```ts
// assets/projects/claude-code/src/Tool.ts
isConcurrencySafe: options.isConcurrencySafe ?? (() => false),
isReadOnly: options.isReadOnly ?? (() => false),
```

## 默认路径与可选路径

默认路径可以压成一句话：模型产生 `tool_use`，query loop 收集它，调度器按 `isConcurrencySafe(input)` 分批或排队，单工具走统一执行管线，结果映射成 `tool_result`，大输出按阈值持久化，历史上下文再做 aggregate budget。

可选路径改变的是内部时机和输出形态，不改变外壳。StreamingToolExecutor 让工具提前执行；Bash background task 让长命令继续跑；Agent 工具在内部启动嵌套 query；MCP 的 PostToolUse hook 可以更新输出；ToolSearch 返回 `tool_reference` 暴露 deferred schema。它们最终仍要让下一轮模型看到结构合法、顺序稳定的工具反馈。

## 非流式调度按批次运行

非流式 fallback 在 `toolOrchestration.ts`。它先把 tool_use 分批：连续并发安全工具放进同一批，独占工具单独成批。这样可以在不破坏顺序语义的前提下并行读文件、搜索等安全工具。

```ts
// assets/projects/claude-code/src/services/tools/toolOrchestration.ts
if (isConcurrencySafe && acc[acc.length - 1]?.isConcurrencySafe) {
  acc[acc.length - 1]!.blocks.push(toolUse)
} else {
  acc.push({ isConcurrencySafe, blocks: [toolUse] })
}
```

同一批并发工具会走 `runToolsConcurrently()`，并发上限来自 `CLAUDE_CODE_MAX_TOOL_USE_CONCURRENCY`，默认 10；独占批次走 `runToolsSerially()`。

```ts
// assets/projects/claude-code/src/services/tools/toolOrchestration.ts
function getMaxToolUseConcurrency(): number {
  const envValue = process.env.CLAUDE_CODE_MAX_TOOL_USE_CONCURRENCY
  if (envValue) {
    const parsed = parseInt(envValue, 10)
    if (!isNaN(parsed) && parsed > 0) return parsed
  }
  return 10
}
```

## 流式调度是状态机

`StreamingToolExecutor` 让工具更早开始执行，但它不是简单线程池。每个 tracked tool 有 `queued`、`executing`、`completed`、`yielded` 状态，并保存 pending progress 和最终 message。

```ts
// assets/projects/claude-code/src/services/tools/StreamingToolExecutor.ts
type TrackedTool = {
  block: ToolUseBlock
  assistantMessage: AssistantMessage
  status: 'queued' | 'executing' | 'completed' | 'yielded'
  isConcurrencySafe: boolean
  messages: Array<MessageUpdate>
  pendingProgress: Array<MessageUpdate>
}
```

能不能启动新工具由 `canExecuteTool()` 决定：当前没有 executing tool 可以启动；或者新工具并发安全，而且所有正在执行的工具也并发安全。只要有一个独占工具在跑，后续工具就排队。

```ts
// assets/projects/claude-code/src/services/tools/StreamingToolExecutor.ts
private canExecuteTool(isConcurrencySafe: boolean): boolean {
  const executingTools = this.trackedTools.filter(t => t.status === 'executing')
  if (executingTools.length === 0) return true
  return isConcurrencySafe && executingTools.every(t => t.isConcurrencySafe)
}
```

最终输出仍要按原顺序。`getCompletedResults()` 可以先吐 progress，但最终 `tool_result` 只输出已经 completed 且轮到顺序的工具。遇到正在执行的独占工具时，它会停住，避免后面的结果越过它。

```ts
// assets/projects/claude-code/src/services/tools/StreamingToolExecutor.ts
for (const tool of this.trackedTools) {
  if (tool.status === 'yielded') continue
  if (tool.status === 'completed') {
    tool.status = 'yielded'
    for (const message of tool.messages) yield message
  } else if (tool.status === 'executing' && !tool.isConcurrencySafe) {
    break
  } else {
    break
  }
}
```

## 单个工具先过校验和权限

调度器只解决“什么时候跑”。单个工具真正执行时会进入 `runToolUse()`，先查 tool 是否存在，再进入统一执行管线。

```ts
// assets/projects/claude-code/src/services/tools/toolExecution.ts
const tool = findToolByName(toolUseContext.options.tools, toolUse.name)
if (!tool) {
  return [createUnknownToolResult(toolUse)]
}

for await (const update of streamedCheckPermissionsAndCallTool(
  tool,
  toolUse.id,
  toolInput,
  toolUseContext,
  canUseTool,
  assistantMessage,
  messageId,
  requestId,
  mcpServerType,
  mcpServerBaseUrl,
)) {
  yield update
}
```

输入校验发生在工具调用之前。schema 或 `validateInput()` 失败会直接产生 error tool_result，工具本体不会执行。

```ts
// assets/projects/claude-code/src/services/tools/toolExecution.ts
const isValidResult = tool.inputSchema.safeParse(input)
if (!isValidResult.success) {
  return [{
    message: createUserMessage({
      content: [{ type: 'tool_result', tool_use_id: toolUseID, is_error: true, content }],
      toolUseResult: `Error: ${content}`,
    }),
  }]
}
```

## Hooks 和 Permission 包住 tool.call

PreToolUse hook 在 permission 前运行。它可以产出 progress/attachment、修改 input、阻断继续，或者给出权限结果。随后 `resolveHookPermissionDecision()` 把 hook result 和 `canUseTool` 合并。

```ts
// assets/projects/claude-code/src/services/tools/toolExecution.ts
for await (const hookResult of runPreToolUseHooks(
  toolUseContext,
  tool,
  toolUseID,
  messageId,
  processedInput,
  requestId,
  mcpServerType,
  mcpServerBaseUrl,
)) {
  hookMessages.push(hookResult)
}

const resolved = await resolveHookPermissionDecision(...)
const permissionDecision = resolved.decision
```

只有最终 `permissionDecision` 是 allow，才会调用 `tool.call()`。这里会传入 toolUseId、是否被用户修改过、canUseTool、parent assistant message 和 onProgress。

```ts
// assets/projects/claude-code/src/services/tools/toolExecution.ts
const result = await tool.call(
  callInput as never,
  {
    ...toolUseContext,
    toolUseId: toolUseID,
    userModified: permissionDecision.updatedInput !== undefined,
  },
  canUseTool,
  assistantMessage,
  onProgress,
)
```

## Result Mapping 决定模型看到什么

工具内部返回 `ToolResult<TOutput>`，但 Claude API 要的是 `tool_result` block。每个工具用自己的 `mapToolResultToToolResultBlockParam()` 做映射。

```ts
// assets/projects/claude-code/src/services/tools/toolExecution.ts
const mappedToolResultBlock = tool.mapToolResultToToolResultBlockParam(
  result.data as never,
  toolUseID,
)

const addToolResult = async (overrideMappedToolResultBlock?: ToolResultBlockParam) => {
  const toolResultBlock = overrideMappedToolResultBlock
    ? await processPreMappedToolResultBlock(tool, overrideMappedToolResultBlock, toolUseID)
    : await processToolResultBlock(tool, result.data, toolUseID)
  toolResultMessages.push(createUserMessage({ content: [toolResultBlock] }))
}
```

MCP 是一个关键分支。非 MCP 工具会先写 tool_result 再跑 PostToolUse hook；MCP 工具的 PostToolUse hook 可能更新输出，所以结果写入时机放到 hook 后。

```ts
// assets/projects/claude-code/src/services/tools/toolExecution.ts
if (!isMcpTool(tool)) {
  await addToolResult(toolOutput, mappedToolResultBlock)
}

for await (const hookResult of runPostToolUseHooks(...)) {
  hookMessages.push(hookResult)
}

if (isMcpTool(tool)) {
  await addToolResult(toolOutput)
}
```

## 第一层结果治理是单次大输出持久化

`toolResultStorage.ts` 先处理单个工具本次输出。如果超过工具自己的 `maxResultSizeChars`，完整输出会写入 session 下的 `tool-results`，上下文里只保留 `<persisted-output>` 路径和预览。

```ts
// assets/projects/claude-code/src/utils/toolResultStorage.ts
export const TOOL_RESULTS_SUBDIR = 'tool-results'

export function getToolResultsDir(): string | null {
  const projectDir = getProjectDir(getOriginalCwd())
  const sessionId = getSessionId()
  if (!projectDir || !sessionId) return null
  return path.join(projectDir, sessionId, TOOL_RESULTS_SUBDIR)
}
```

```ts
// assets/projects/claude-code/src/utils/toolResultStorage.ts
export function buildLargeToolResultMessage(result: PersistedToolResult): string {
  return `<persisted-output>
Full output has been saved to: ${result.path}

Preview:
${result.preview}
</persisted-output>`
}
```

这一步解决单次结果过大的问题。例如 Bash 打印 100k 行日志，模型不应该在下一轮上下文里看到完整日志；它看到路径、预览和明确的 persisted-output 标记即可。

## 第二层结果治理是历史预算

下一轮模型调用前，`query.ts` 会调用 `applyToolResultBudget()`。它处理的是历史 messages 中聚合后的 tool_result 预算，运行在 microcompact 之前。

```ts
// assets/projects/claude-code/src/query.ts
messagesForQuery = await applyToolResultBudget(
  messagesForQuery,
  toolUseContext.contentReplacementState,
  persistReplacements
    ? records => void recordContentReplacement(records, toolUseContext.agentId).catch(logError)
    : undefined,
  new Set(
    toolUseContext.options.tools
      .filter(t => !Number.isFinite(t.maxResultSizeChars))
      .map(t => t.name),
  ),
)
```

`ContentReplacementState` 保存 seenIds 和 replacements。已经替换过的 tool_use_id 会复用同一个 replacement，这样 resume 或下一轮请求不会因为路径、模板或选择变化破坏 prompt cache。

```ts
// assets/projects/claude-code/src/utils/toolResultStorage.ts
export type ContentReplacementState = {
  seenIds: Set<string>
  replacements: Map<string, ContentReplacement>
}
```

## Bash、Agent、MCP、ToolSearch 都有特殊路径

Bash 默认结果上限是 30,000 字符，并且只有 read-only 输入可并发。它还可能把长输出在工具内部先持久化，然后映射成 `<persisted-output>`。

```ts
// assets/projects/claude-code/src/tools/BashTool/BashTool.tsx
maxResultSizeChars: 30_000,
isConcurrencySafe(input) {
  return this.isReadOnly?.(input) ?? false
},
```

Agent 表面上也是工具，外层有 tool_use_id 和 tool_result；内部却可能重新运行 query、拥有自己的工具池、权限、abort controller、transcript 和结果预算状态。

```ts
// assets/projects/claude-code/src/tools/AgentTool/AgentTool.tsx

  return true
},
isReadOnly() {
  return true
},
```

## 失败也是 tool_result

工具失败不会只变成 throw。`toolExecution.ts` 会运行 failure hooks，并产出带 `is_error: true` 和原 `tool_use_id` 的 `tool_result`。这样模型知道哪一次工具调用失败了，可以据此修正下一步。

```ts

  toolUseContext,
  tool,
  toolUseID,
  messageId,
  processedInput,
  content,

  requestId,
  mcpServerType,
  mcpServerBaseUrl,

  hookMessages.push(hookResult)
```

## 可复用设计

- **并发能力由工具自声明**：调度器不维护工具名白名单，只问 `isConcurrencySafe(input)`。
- **统一执行插槽包住工具业务**：schema、validateInput、PreToolUse、permission、tool.call、PostToolUse、failure hook 各有位置。
- **最终顺序要稳定**：流式执行可以提前启动工具和吐 progress，但最终 tool_result 要按原 tool_use 顺序进入上下文。
- **结果治理分两层**：单次输出超限先落盘，历史聚合预算再做稳定替换。
- **特殊工具也服从外壳**：Bash、Agent、MCP、ToolSearch 的内部很不同，但都必须回到 tool_result 或 tool_reference 协议。
